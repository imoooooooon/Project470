1. Introduction
1.1 Purpose
This document describes the software requirements for Krishi Bondhu. Krishi Bondhu aims to help farmers in Bangladesh sell crops at fair prices and manage their farming needs. It connects farmers with buyers, workers, and veterinary doctors. It also provides market prices, cattle records, and farming guidance. Bangla text and voice support help farmers use the platform.
1.2 Scope
Krishi Bondhu is a web-based platform for farmers and other agricultural users in Bangladesh. It helps farmers sell crops directly to buyers, negotiate prices, and receive payments through the platform.
The platform covers five main service areas:
* Crop marketplace: Farmers can list crops for sale. Buyers can search for crops, negotiate prices, and place orders.
* Cattle breeding records: Farmers and insemination agents can keep cattle profiles, breeding records, and family history.
* Market prices: Users can view local market prices, compare prices, and find nearby markets.
* Crop and animal health guidance: Farmers can get basic guidance about crop diseases, animal health, and fertilizers. They can also find veterinary doctors.
* Worker booking and Bangla support: Farmers can find and book agricultural workers. Bangla text and voice features help users access the platform.
The platform serves farmers, buyers, agricultural workers, insemination agents, market price contributors, veterinary doctors, agricultural product sellers, and administrators.
Krishi Bondhu will not run its own delivery service or perform physical soil tests. It can help users arrange delivery and use existing soil-test results for fertilizer guidance.


2. Overall Description
2.1 Product Perspective
Krishi Bondhu is an independent web-based platform for agricultural users in Bangladesh. Its intended users currently rely on phone calls, middlemen, paper records, and separate services for many farming tasks. Krishi Bondhu brings crop trading, cattle records, market prices, health guidance, and worker booking into one place. It supports these activities by helping users share information, keep digital records, and connect with each other.
2.2 Product High-Level Summary
Krishi Bondhu will provide the following main functions:
* Accounts and roles: Users can access multiple roles through one account. For example, a farmer can also buy crops or work on another farm.
* Crop marketplace and payments: Farmers can manage crop listings. Buyers can search for crops, negotiate prices, place orders, and pay through the platform.
* Cattle breeding records: Farmers and insemination agents can maintain cattle profiles and breeding records. The system can track family history and warn about possible inbreeding.
* Market information: Users can view crop prices, compare local markets, and find market locations. They can also view past prices to help plan crop sales.
* AI-based farming guidance: The system can suggest possible crop and animal diseases using photos or symptoms. It can also suggest fertilizers using available soil information.
* Veterinary services: Farmers can find nearby veterinary doctors and contact them for animal healthcare.
* Agricultural worker booking: Farmers can post jobs and book workers. Workers can find jobs, apply, and negotiate wages.
* Bangla support: Bangla text, voice commands, spoken responses, and simple visual controls help users access the platform.
* Administration: Administrators can manage users and listings. They can also review complaints and monitor platform activities.
2.3 Users and Characteristics
Krishi Bondhu has eight user roles. One person can use more than one role through the same account.

2.4 Operating Environment
Krishi Bondhu will initially run as a web application. Users can access it through a modern web browser on a smartphone or computer.
An internet connection is required for all main tasks. Low-data mode will help users access the platform on slow connections.
Users must allow microphone access to use voice features. For location-based features, users can allow location access or enter their location manually. Devices must support Bangla text display and audio playback for Bangla text and spoken responses.
2.5 Design and Implementation Constraints
This project will follow the CSE470 rules, including the required MVC architecture.
(a) Primary Technology Stack
The application will use PHP with Laravel for the backend. The frontend will use Blade templates, HTML, CSS, Bootstrap, and JavaScript. MySQL will store the application data.
(b) MVC Framework and Structure
Laravel will organize the application into three parts:
* Model (app/Models): Manages application data and relationships.
* View (resources/views): Displays pages and forms using Blade templates.
* Controller (app/Http/Controllers): Handles user requests and connects models with views.
Separate service classes will handle complex tasks, such as price calculations and AI requests.
(c) AI Features and Service
The proposed AI service is Gemini API. It will support suggestions about possible crop and animal diseases and suitable fertilizers. Laravel will call Gemini directly from the server. FastAPI will not be used.
The team plans to use a model with a free tier for initial development and testing. AI features will depend on API availability and usage limits. The API key will remain on the server. The team will confirm the proposed AI approach with the faculty.
(d) Faculty-Approved Exceptions
No faculty-approved exceptions to the course’s technology rules have been granted.

* Users will provide correct information about crops, cattle, products, and jobs.
* Market price contributors will enter and update prices manually. Prices will depend on their updates.

* External services may have free usage limits. Features that use these services may be temporarily unavailable when a limit is reached.
3. System Architecture
3.1 Architectural Overview
Krishi Bondhu will use Laravel and follow the MVC architecture. It will run as one web application connected to a MySQL database.
The application will have six main areas: accounts, marketplace and payments, cattle records, market information, health guidance, and worker booking. Bangla text and voice support will work across supported tasks.
Model: Models will manage data and relationships. Examples include User, CropListing, Order, Cattle, and Booking.
View: Blade templates will display pages and forms. Bootstrap will help the pages fit phone and computer screens.
Controller: Controllers will receive user requests, check permissions, and coordinate actions between models and views.
Separate service classes will handle complex tasks, such as price calculations, breeding checks, and external API requests.
  

For example, when a farmer submits a crop listing, the controller checks the request and the farmer’s permission. The model saves the listing in the database. The controller then returns a view showing the result.
Each user will have one account and may hold several roles. The backend will check the user’s permissions before allowing access to protected actions.
